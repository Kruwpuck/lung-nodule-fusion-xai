# Rev1 Review — Task Board

Single source of truth for the crew implementing `docs/Review Revisi 1.md`.
Every agent reads this file before starting and edits it before finishing.

## Status vocabulary

| Status | Meaning |
|---|---|
| `todo` | Not started. |
| `blocked` | A dependency is not yet `done-code` or `done`. |
| `in-progress` | Claimed by the agent named in Owner. |
| `done-code` | Code and tests landed and green, but the experiment still needs a GPU run. |
| `needs-gpu` | Handed back to the human: only a remote GPU run remains. |
| `done` | Code landed and results regenerated. |

## Hard rules for every agent

1. Claim exactly one task per invocation. Set it `in-progress` with your agent name in Owner, then do the work.
2. This machine has no usable GPU. Never launch training, sweeps, or full ablation re-runs locally. Write the code, write the tests, run `pytest`, then set the task to `done-code` and add a `needs-gpu` note describing the exact command to run remotely.
3. Tests first when the behavior is assertable. Run `pytest tests/ -q` before you report finished. A red suite means the task is not done.
4. Never edit `paper/refs.bib` (Zotero auto-export) and never invent a citekey. If a key is missing, say so in your Notes line.
5. Never run `git commit` or `git push`. The human commits.
6. Additive only. Do not delete or overwrite existing checkpoints under `artifacts/`, existing result CSVs, or the legacy 6-model config block.
7. When you finish, append one line under Findings with what you changed and anything the next agent must know.
